# whalegirl-pet-kit

给 [PetPet](https://github.com/stshourenxy-dev/petpet-playbook) 桌宠框架做素材的工具链：**从一张立绘、几段 AI 生成的视频，做出能跑的宠物包**。

> **用这套工具跑出来的成品**：[鲸鱼娘桌宠](https://github.com/wei125775-lab/whalegirl-deskpet) —— 14 个动作，Claude Code / dsh 双端，含一份 229 行的踩坑文档。想知道这条流水线走到最后长什么样、哪些坑会再撞一次，看它。

仓库里只有脚本和方法，**不含任何美术素材**（立绘和视频都是 AI 生成的，版权归属不清晰，不适合公开）。你拿自己的图跑一遍就能得到自己的宠物。

---

## 这套东西解决什么

桌宠的素材难点不在于"画得好看"，而在于**动作要连贯、尺寸要一致、循环要闭合**。这三件事手工做都很痛苦，AI 生成又有各自的问题。这套脚本把中间那段自动化了：

| 问题 | 做法 |
|---|---|
| AI 生成的视频里角色会漂移、倾斜 | 逐帧锚点配准 + 绕脚底直立化 |
| 各条视频的角色大小不一致 | 按实测身高归一 |
| 视频是绿幕/白底，要抠成透明 | 自适应色度抠像 + despill |
| 不同来源的素材有色差 | 以基准动作拟合并统一 |
| 动作首尾接不上 | pingpong 往返播放 / 找闭合切点 |
| 待机的小幅呼吸感 AI 画不出来 | 从分层 PSD 程序化烘焙 |

最后一条是核心判断：**大动作（挥手/吃饭/跳跃）交给 AI 生成视频，微动（待机呼吸/飘发/眨眼）必须程序驱动**。AI 画小幅度动作时，帧与帧之间的不一致会暴露成抖动，肉眼非常敏感；反过来，让它画"抬手挥手"这种大幅动作反而质量不错。

## 依赖

```bash
pip install numpy pillow scipy opencv-python psd-tools
pip install rembg          # 可选，处理非绿幕的抠图
```

补帧需要 [RIFE](https://github.com/nihui/rife-ncnn-vulkan)（ncnn+Vulkan 版，不需要 torch，核显就能跑）。脚本里的路径要按你的实际位置改。

**注意：所有脚本里都有硬编码的绝对路径常量**（源素材目录、输出目录、RIFE 位置），跑之前先看文件头的常量区改成你自己的。

## 路线 A：AI 视频 → 序列帧动作

适用于：挥手、吃饭、跳跃这类大幅动作。

1. **生成** 用可灵/即梦/豆包之类的图生视频，拿一段 3~5 秒的动作视频。**背景务必用纯绿幕**——白底会把白围裙、白蕾丝一起抠穿。提示词里写明"手臂离开身体，与躯干之间留出背景空隙"，否则模型分不清手臂边界，动起来会把头发一起拽着走。

2. **抽帧 + 抠像 + 配准**
   ```bash
   python tools/build_video.py <动作名>
   ```
   一条命令走完：抽帧 → 清水印 → 自适应抠像 → 身高归一 → 配准（脚底 + 水平中心）→ 直立化 → 输出精灵表/GIF/检查图。

3. **颜色对齐**（多条动作来自不同视频时）
   ```bash
   python tools/match_color.py
   ```
   以某一条为基准，逐通道线性拟合其他条，消除色差。

4. **补帧**（可选）
   ```bash
   python tools/rife_tween.py <动作名>
   ```
   12fps → 24fps。注意 RIFE 在"手臂从无到有"这种大跳变处生不出中间形态，只适合已经比较连贯的素材。

5. **拆动作**（可选）
   ```bash
   python tools/split_eat.py
   ```
   把一条完整动作拆成若干段重复使用。比如"吃饭"可以拆成"吃"（循环）和"收碗"（一次性）。

---

## 路线 B：分层 PSD → 待机微动

适用于：待机呼吸、头发飘动、眨眼。

1. 用 [see-through](https://github.com/ModelsLab/see-through) 把立绘拆成图层 PSD（建议输入 ≥1024px、正面直立、手臂离开身体）。会得到后发/前发/脸/眼睛各层/衣服各层之类的结构。

2. 烘焙：
   ```bash
   python tools/build_idle_layers.py
   ```
   三路正弦叠加：呼吸（绕脚底纵向缩放）+ 摇摆（越往上越大）+ 飘动（头发和尾巴按行波抖），外加眨眼（把眼球层绕眼睛中线纵向压扁）。

   分层驱动的意义在于：合成成一张图之后，距离变换会把头发和身体看成同一坨，飘动权重传不到发梢；分开算才能让长发外侧和尾巴比身体多摆。

### 没有 PSD 的退路：`pose_rig.py`

上面那条路的前提是 see-through 能分出图层。**手里只有一张透明立绘**时（比如想给"托腮""害羞"这类静态姿势做微动）走这条：

```bash
python tools/pose_rig.py
```

同样是三路正弦叠加（呼吸 / 摇摆 / 飘动），但**不分层**——对整张图算位移场，按"细长部位"（发丝、尾巴边缘）加权。

代价是**没有眨眼**：眨眼要求眼球是独立图层，单张图做不到。所以这条适合静态姿势，待机那种要眨眼的还是得走分层。

## 踩过的坑

这部分比脚本本身值钱，都是实测撞出来的。

### 抠像

- **`G - max(R,B)` 在 uint8 下会环绕**。负数变成 200 多的大正数，整个角色被判定成背景，输出只剩一层轮廓线。**抠像函数第一行必须 `p.astype(np.float32)`**。
- **AI 生成视频的背景绿远不如绿幕素材纯**。实测 `G-max(R,B)` 只有 49~61（纯绿幕是 200+），写死阈值必然失效。要从每条视频自己的背景采样，按分位数定阈值。
- **水印会漂移**。同一条视频里，水印可能在右下角待一会儿又跑到左上角。固定矩形清除治不了，要用连通域法：主体是最大的一块，其余离它超过 N 像素的全清。注意 N 要选在"清得掉水印、留得住角色附属元素（比如比心的红心）"之间。
- **角色脚下有接地淡影**（AI 生成时的投影，alpha 10~40）。它离主体只有几像素，连通域法够不着，抬 alpha 阈值又会啃掉角色的抗锯齿边。解法是按列找主体下沿，之下全清——脚底以下本来就没角色内容。
- **轮廓外有一圈雾**。H.264 在角色和背景之间留了一层过渡像素，抠像后是 alpha 20~150 的边，深色底上看就是一圈白晕（蕾丝和发丝最明显）。清法是 alpha 低于阈值归零再重新拉伸；只清零不拉会在边缘留台阶。

### 几何

- **各条视频里角色大小不一致**。同一套流程生成的不同动作，实测角色身高能差 2%（642px vs 652px）。不统一的话切换动作时忽大忽小。
- **缩放要作用在"角色相对画面"的比例上**。第一版是把整张图缩放，结果贴回固定画布时两个缩放互相抵消，白改。正确做法是把 `画布高/图高` 换成 `目标身高/实测身高`。
- **直立化的目标角度不能用"各条自己的中位"**。有一条视频里角色整体就歪着 1.7 度，转回自己的中位等于保持歪。要用统一的目标角度。
- **配准锚点用脚不用头**。角色不是刚体，AI 生成的视频里躯干相对头部会有位移。把头钉死，这个位移就全暴露在脚上（脚在画布上左右滑十几像素，肉眼就是"斜了一下"）；钉脚则表现为上身自然晃动。

### 性能与工具

- **低分辨率素材上"位移即糊化"**。位移超过结构自身宽度时，双线性插值会把细节抹平，播放时表现为"一糊一清"的脉动。解法是超采样——在 3 倍分辨率上做变形再降回来。
- **`cv2.remap` 只吃 `CV_32FC1`**。位移场里只要有 Python float 参与运算就会升成 float64，报错信息很难懂。
- **PIL 的 `Image.paste(src, xy, mask)` 会再乘一次 alpha**，边缘被压暗形成暗边。要用预乘 alpha 走 numpy 通道运算。
- **ffmpeg/RIFE 的透明帧处理**：RIFE 吃 RGB 不认 alpha，直接喂透明 PNG 会把透明区当黑色物块。要走"RGB 合成到中性底 → 送 RIFE → 解合成"，alpha 单独跑一趟（不能线性平均，否则位移大的动作会出现双层半透明影子）。

### 时间轴

抽帧那一步埋着两个坑，素材看着没问题、播起来才不对劲：

- **均匀抽帧会把"动作之外"的帧一起抽进来**。`build_video.py` 是 `np.linspace(0, total-1, n)`，按**整条视频**等间隔切，不是按动作边界切。所以每条轨道开头挂着她还没起手的站桩、结尾挂着做完之后的回位，有时还混进下一段动作的起手。判断法：取整条轨道相邻差的中位数，**低于它 35% 的连续首/尾段就是死帧**，直接剪掉。注意区分"死帧"和"有意的保持"——表情类动作中间那些小差异是动作本身（保持得意表情、红心成型后停一拍），别剪。
- **抽 30 帧按 12fps 播 = 2 倍速**。源视频 121 帧 / 24fps = 5.04 秒，抽成 30 帧后按 12fps 播只剩 2.5 秒，**整个动作快了一倍**。这是设计如此（12fps 是精灵动画的常规速率），一直没人抱怨；但哪天觉得动作太急，先对上这一条再改别的。往返播放的素材（`eat` 那种）前向速度本来就和源视频接近，改速要连它一起改，否则两种吃法会一快一慢。

## 宠物包格式

`pet-template/pet.json` 是配置模板，字段含义见 [petpet-playbook 的接口协议](https://github.com/stshourenxy-dev/petpet-playbook/blob/main/docs/08-接口协议.md)。

几个实用的点：

- **`weight: 0`** = 不参与随机播放，但托盘菜单和程序触发仍能用。想让宠物"只做某个动作"就把其他的都设 0。
- **`pingpong: true`** = 往返播放。**素材找不到天然闭合的循环段时，这是最省事的解法**——正放接倒放必然连续。注意它需要 `loop: true` 配合。
- **`transitions`** = 动作间的转移链。播完 A 之后按权重选下一个动作，用来表达"吃完饭接着发呆"这类行为关联。
- **精灵表总宽 ≤ 16384px**（WebGL 纹理上限，超了直接黑屏）。30 帧 × 每个 546px 就是上限了。

**同一批序列帧也能打成 dsh 的 frames2d 格式**（逐帧 PNG + manifest v2），不用重跑流程。dsh 侧另有一批自己的坑——轨道名不许有下划线（会让整条轨道被拒）、单轨最多 64 帧（超了整只宠物被静默丢弃）、frames2d 没有 pingpong 所以循环素材得手工展开成往返序列——都整理在[鲸鱼娘桌宠的 README](https://github.com/wei125775-lab/whalegirl-deskpet)里。
